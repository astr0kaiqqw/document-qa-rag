# Document QA — локальное приложение

Загрузите PDF, DOCX, TXT, PNG, JPG/JPEG или WEBP, задайте вопрос и получите **фрагмент исходного документа** с именем файла, страницей и окружающим абзацем. Приложение работает на Streamlit. Текстовый путь использует embeddings + FAISS и прежнюю extractive QA. Изображения и сканированные страницы обрабатывает локальная Qwen3-VL через Ollama; её ответы генеративные и требуют проверки. Облачные inference API не используются.

## Запуск на этом компьютере

Зависимости установлены, QA-модель скачана, embedding-модель доступна локально. Из корня проекта:

```bash
./run_app.sh
```

Откройте **http://127.0.0.1:8501**. Если сервер уже запущен, достаточно открыть эту ссылку.

Эквивалентная команда:

```bash
.venv/bin/streamlit run app.py
```

Для другого порта: `./run_app.sh --server.port 8502`. Остановка — `Ctrl+C` в терминале сервера. Скрипт запуска включает offline mode; приложение также устанавливает offline flags само. По умолчанию сервер доступен только на этом компьютере, telemetry Streamlit отключена.

## Установка с нуля

Проверенное окружение: Python **3.14.7**, macOS ARM64. На другой платформе нужны совместимые wheels PyTorch/FAISS.

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/setup_models.py
./run_app.sh
```

Только установка пакетов и первоначальная загрузка моделей требуют интернета. `setup_models.py` скачивает **один QA checkpoint** и embedding-модель в ignored `models/`; это около 1,6 ГБ весов суммарно. Подготовьте несколько гигабайт диска для загрузки и достаточную оперативную память; inference выполняется на CPU. Никаких credentials для публичных моделей не требуется. Не запускайте setup повторно для обычного использования: после подготовки приложение работает offline. При прерванной загрузке повторите setup.

`requirements.txt` закрепляет прямые зависимости, `requirements-lock.txt` — фактическое установленное окружение. Streamlit 1.66.1 и sentencepiece 0.2.2 добавлены к существующему `.venv`; PyTorch/Transformers не заменялись.

## Как пользоваться

1. В левой панели выберите один или несколько PDF/DOCX/TXT/PNG/JPG/WEBP и нажмите **«Обработать файлы»**.
2. Выберите нужный документ в списке.
3. Введите вопрос и нажмите **«Найти ответ»**. Первая загрузка моделей может занять больше времени.
4. Прочитайте ответ, имя источника, номер страницы PDF и подтверждающий фрагмент.
5. Задайте следующий вопрос или переключите документ. История хранится отдельно для каждого файла.
6. **«Сбросить сессию»** удаляет загруженные временные файлы, индексы и историю текущей сессии. Общие read-only модели остаются в памяти для быстрого повторного использования.

Можно держать до 8 документов, до 25 МБ каждый. TXT должен быть в UTF-8. PDF может содержать обычный текст, сканы или оба типа страниц: OCR выполняется автоматически при наличии Tesseract. DOCX извлекается из основных абзацев; таблицы, headers и footers отдельно не читаются. Для TXT/DOCX номер страницы не придумывается — интерфейс сообщает, что его нет.

Документы не отправляются в облако. Они временно хранятся в отдельном каталоге сессии; постоянная библиотека документов и авторизация не входят в приложение. Это локальный учебный проект, не сервер для публичного размещения. При перезапуске процесса загруженные документы нужно добавить заново.

## Какая модель используется

В приложении — **[deepset/xlm-roberta-base-squad2](https://huggingface.co/deepset/xlm-roberta-base-squad2)**, `XLMRobertaForQuestionAnswering`, около 0,3B параметров. Это multilingual XLM-R, fine-tuned для **extractive QA на SQuAD 2.0**, а не text-generation model. QA revision закреплён: `a5fab9908c8d856e8c583fd41ba6d92444e46477`. Attribution: deepset, лицензия checkpoint **CC BY 4.0**; model card сохранена вместе с локальными assets.

Модель поддерживает CLS/null answer. Каждый QA window сравнивает допустимый span с собственным CLS score; если non-null span не побеждает, окно отказывается. Если все найденные evidence contexts отказались, приложение сообщает: **«Надёжный ответ не найден»**. Порог не подбирался по новым benchmark данным, проценты уверенности не выдумываются.

Мультиязычная основа позволяет задавать EN/RU/KK вопросы, но QA fine-tuning проводился на английском SQuAD 2.0. Равное качество русского и казахского **не гарантируется**. Любой непустой ответ показан как **извлечённый кандидат**, который нужно сверить с источником; null detection тоже может ошибаться.

Прежний BERT в `models/final_qa_model/` и training notebook не изменены. `QAModel` сохранён для совместимости старых scripts/tests, а пользовательское приложение явно использует `ExtractiveQAModel`. Исторические EM/F1 из `reports/` относятся к предыдущим экспериментам и не объявляются метриками новой модели. Переобучения не выполнялось.

## Что происходит внутри

Upload → исходный текст и page metadata → tokenizer-aware chunks → normalized multilingual MiniLM embeddings → FAISS cosine search → исходные страницы/абзацы найденных chunks → extractive XLM-R → ответ по character offsets → проверка source coordinates → интерфейс.

Индексируются короткие chunks с лимитом 96 tokens, включая special tokens, overlap target 24. Embedding-модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` имеет effective limit 128; silent truncation запрещена. Для QA приложение читает исходные страницы PDF по отдельности либо окружающий абзац TXT/DOCX, сохраняя offsets. Так соседние слайды не смешиваются в один QA input. Длинные inputs проходят через overlapping QA windows 256/128. Answer cap приложения — 64 wordpieces.

Выбор среди допустимых кандидатов — по retrieval similarity; нет length bonus и заявления, что score является вероятностью истины. Word-boundary constraints не позволяют показывать искусственный `##` или случайный корень слова. Результаты не генерируются и не переводятся автоматически.

Код: `app.py` — UI, `document_app/service.py` — изолированные сессии, `rag/` — существующий RAG backend, `scripts/setup_models.py` — одноразовая подготовка, `run_app.sh` — запуск.

## Известные ограничения

Сложные вопросы, повреждённые PDF-формулы, склеенные слова, противоречащие passages и языки вне основного QA training могут приводить к ошибке или ложному отказу. No-answer механизм не даёт абсолютной гарантии; именно поэтому ответы помечены как кандидаты. Слишком длинный вопрос отклоняется явно — сократите его. Не запускайте параллельно несколько тяжёлых копий модели без необходимости.

Веса, caches, `.venv`, загрузки и большие raw runs не входят в Git. Исторические исходники `evaluation/` и аудита в `experiments/` сохранены в Git; сгенерированные результаты аудита остаются локальными и игнорируются. История разработки не переписана; готовое приложение находится в ветке `feat/final-document-qa`.


## OCR и голосовой ввод

OCR выполняется локальным Tesseract с языками `rus+eng`. Обычный текст PDF извлекается первым; только страницы без букв/цифр передаются OCR (PDFium, 216 DPI). Смешанные PDF сохраняют исходные номера страниц. PNG, JPG/JPEG, WEBP проходят OCR целиком. DOCX и UTF-8 TXT обрабатываются прежним способом. Имена файлов, страницы и распознанные фрагменты используются существующим RAG без смены QA-модели.

Установите системные зависимости:

```bash
# macOS
brew install tesseract tesseract-lang
# Ubuntu / Debian
sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
```

Затем подготовьте Python-зависимости и модель речи (один раз с интернетом):

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/setup_speech.py
./run_app.sh
```

Whisper base хранится в `models/whisper-base` (примерно 150 МБ весов). Работает на CPU, int8, 4 потока; выделите дополнительно около 1 ГБ RAM, скорость зависит от компьютера. FFmpeg отдельно не требуется: аудио декодируется PyAV. PyAV ограничен версией ниже 19 из-за совместимости faster-whisper. Во время работы модели ничего не скачивается. Документы и записи не отправляются провайдерам; при удалённом размещении запись передаётся серверу самого приложения.

В рабочей области рядом с вопросом откройте «Микрофон», выберите язык (русский, English или автоматически), начните запись и остановите её той же кнопкой. Нажмите «Распознать запись». Результат появится в поле вопроса; исправьте его и отдельно нажмите «Найти ответ». Повторная попытка распознавания доступна той же кнопкой. Вопрос автоматически не отправляется. Озвучивания ответов нет.

Браузеру нужен доступ к микрофону и localhost или HTTPS. Если доступ запрещён, откройте настройки разрешений сайта, разрешите микрофон и обновите страницу. При отсутствии устройства подключите его/выберите системный вход. Если браузер не поддерживает запись, используйте обычный текстовый ввод. Состояние записи и остановка — штатный виджет Streamlit; ошибки разрешений показывает браузер/виджет. Пустые записи, отсутствие речи, модели и сбои распознавания обрабатываются отдельно.

Ограничения: 25 МБ на документ, 8 документов в сессии, PDF до 100 страниц, изображение/отрисованная страница до 20 млн пикселей, OCR до 45 секунд на страницу, WAV до 60 секунд / 10 МБ. Большие PDF могут обрабатываться несколько минут. Пустые/нечитаемые страницы отмечаются в замечаниях; если текста нет во всём файле, файл не индексируется. Для частичного PDF проверяйте замечания: нераспознанные страницы не участвуют в поиске. OCR ошибается на рукописи, таблицах, размытых фото и формулах; текстовый слой PDF с буквами/цифрами повторно не распознаётся, даже если он низкого качества. Распознанная речь также требует проверки. Наличие текста в OCR не гарантирует, что QA-модель найдёт ответ, особенно на русском.

Интерфейс сохраняет Streamlit: нейтральные графитовые поверхности, изумрудный акцент, серебристая SVG-форма с точками, компактный знак и лёгкий заголовок, отдельная область источника и соседние поля вопроса/микрофона. На узких экранах колонки перестраиваются; документы доступны в раскрываемой боковой панели. Фокус клавиатуры выделен, короткие реакции кнопок отключаются при `prefers-reduced-motion`. Декоративные изображения и внешние шрифты не загружаются.

Референсы: [Builders Table](https://onepagelove.com/builders-table), [Shopify Editions Spring 2026](https://onepagelove.com/shopify-editions-spring-2026). Изучены страницы и мобильные скриншоты обоих; оригинал Builders Table доступен, оригинал Shopify через переход One Page Love не открылся. Брендинг и изображения не копировались.


### Расписания в виде таблицы

Для сканов с чёткой регулярной сеткой OCR дополнительно читает ячейки отдельно и связывает их с распознанными заголовками дней. Пропущенные колонки не додумываются: например, после среды может идти пятница, если так указано в исходнике. Вопросы о времени («во сколько основы кибербезопасности в понедельник?», «когда основы кб в пн?») обрабатываются отдельным поиском по строкам расписания. Выводятся все подходящие интервалы, напечатанные в документе; без дня — все найденные дни. Поддерживаются сокращения «кб» и «бд». Основная QA-модель для остальных документов и вопросов не менялась.

Это ограниченный разбор регулярной сетки, а не универсальное понимание любых таблиц. Неразборчивые заголовки, нестандартная сетка и время, обрезанное в исходном изображении, могут остаться нераспознанными. Если подходящая строка со временем не найдена, приложение не подставляет другой день.

После обновления ранее загруженного документа нажмите «Обработать файлы» ещё раз. Старый результат OCR хранится в сессии до переобработки; повторная обработка обновит индекс и очистит историю этого документа. При необходимости загрузите исходный файл снова. Повторный клик после успешного обновления не создаёт копию.

Регрессионные тесты: `.venv/bin/python -m pytest tests/test_timetable.py -q`. Для дополнительной проверки на личном PDF без его копирования в репозиторий задайте переменную окружения `DOCUMENT_QA_SCHEDULE_PDF` с путём к файлу и запустите те же тесты. Этот дополнительный тест рассчитан на исследованное расписание; остальные тесты используют искусственные примеры.


## Два пути: QA по тексту и локальная модель по изображению

**Установленный вариант:** Ollama `qwen3-vl:4b-instruct`, Qwen3-VL 4B Instruct, Q4_K_M. Официальный manifest на момент установки: 3 337 225 651 байт (~3,34 ГБ) с vision projector. Проверено на Apple M4 / 16 ГБ RAM; при контексте 8192 Ollama показывала ~4,47 ГБ памяти модели на GPU. Дополнительно нужны RAM для Python/QA/embeddings и системы, свободное место для весов и временных изображений. Интернет нужен только для установки/скачивания.

Ollama уже установлена и модель скачана на этом компьютере. Qwen3-VL требует Ollama 0.12.7 или новее; проверенная версия — 0.40.16. На другой машине установите Ollama с [официального сайта](https://ollama.com/download), запустите локальный сервис и один раз выполните:

```bash
# Отдельный терминал, если Ollama ещё не запущена
./scripts/start_vision.sh
# Другой терминал: одноразовая загрузка, не при каждом старте приложения
ollama pull qwen3-vl:4b-instruct
./run_app.sh --server.port 8502
```

Скрипт сервера использует 127.0.0.1, отключает cloud-функции и ограничивает параллельность. Не запускайте вторую Ollama на том же порту. Приложение подключается только к loopback HTTP, игнорирует HTTP-прокси, запрещает перенаправления, cloud-теги и удалённые aliases; перед запросом проверяет локальные веса и vision capability. Вопрос и изображение не отправляются на внешние серверы. Никакого автоматического скачивания, обучения или скрытого переключения при отказе QA нет.

Настройки перед запуском Streamlit:

```bash
export DOCUMENT_QA_OLLAMA_URL=http://127.0.0.1:11434
export DOCUMENT_QA_VISION_MODEL=qwen3-vl:4b-instruct
export DOCUMENT_QA_VISION_TIMEOUT=180
```

Таймаут от 1 до 600 секунд на страницу, 3–5 секунд на проверку готовности. На запрос выбирается до двух страниц; при двух страницах время может суммироваться. Контекст визуальной модели ограничен 8192, ответ — 600 токенами. Для модели явно отключено внутреннее thinking, если сервис поддерживает этот параметр. После ответа модель выгружается (`keep_alive: 0`); следующий запрос загрузит уже скачанные веса с диска. Это экономит RAM, но добавляет задержку. QA и визуальная модель выполняются последовательно под общей блокировкой ресурса; визуальный клиент дополнительно имеет общую блокировку между сессиями, без бесконечных повторов. Аудиомодель остаётся локальной.

Маршрутизация:

- TXT / DOCX: прежние извлечение → поиск → extractive QA.
- PNG / JPG / JPEG / WEBP: оригинал + вопрос → Qwen3-VL. OCR остаётся для поиска; пустой OCR не делает игру или схему непригодной для визуального вопроса.
- PDF: тип хранится для каждой страницы. Если букв/цифр меньше 40 или растровые изображения занимают от 35% площади, страница считается визуальной. Это эвристика, включая случай частичного текстового слоя; полное определение всех таблиц/схем не обещается.
- Для больших PDF OCR/обычный текст участвуют в выборе до двух страниц. Если поискового текста нет, выберите страницу вручную; все страницы в каждый запрос не передаются.
- Если среди найденных страниц есть визуальная, выбранные страницы читаются по изображениям. Для обычного текста используется QA; её контексты ограничиваются текстовыми страницами. Слова о таблице/формуле/схеме в вопросе могут явно направить PDF на визуальный путь. Это выбор до выполнения QA, а не скрытый повтор после отказа.
- В интерфейсе можно выбрать «По изображению страницы» и нужную страницу даже для текстового PDF. Это полезно для векторных формул/схем, которые эвристика не заметила. «QA по тексту» не применяется к странице с неполным текстовым слоем. Явно выбранная текстовая страница передаётся QA непосредственно как источник.

Оригиналы сохраняются в принадлежащей сессии временной папке. PDF рендерится локально до 216 DPI, с ограничением 20 млн пикселей. Для широких/больших изображений клиент передаёт overview и 2–4 перекрывающихся детали в порядке строк; каждая сторона подготовленного вида ограничена 1280. Такой бюджет не гарантирует чтение очень мелкого текста: выберите отдельную страницу или загрузите более чёткий фрагмент. Оригинал не перезаписывается. Показанное изображение можно раскрыть под ответом и скачать исходный файл.

Каждый результат подписан «QA по тексту» либо «Локальная модель по изображению». Для визуального ответа показываются имя файла, страницы и исходное изображение. Генеративный текст не выдаётся за дословную цитату, проверенный факт или процент уверенности. Содержимое изображения передаётся как недоверенные данные; модель не получает инструментов и инструкций выполнять действия из документа. Отсутствующие/нечитаемые данные должны приводить к отказу, но модель всё равно может ошибаться.

Готовность Ollama видна в боковой панели, есть «Проверить модель». При отсутствии сервиса/модели, недостатке памяти, timeout или некорректном ответе выводится отдельная ошибка; текстовое поле остаётся доступным. Старые документы версии обработки 2 нужно переобработать кнопкой загрузки — оригиналы не удаляются автоматически.

Проверки:

```bash
.venv/bin/python -m pytest -q
# Реальные локальные модели; пишет результаты в reports/multimodal_update/
.venv/bin/python scripts/check_multimodal.py
```

Второй скрипт использует доступные локальные пользовательские лекцию/расписание и диагностическую копию слайда, плюс явно обозначенные тестовые формулу, производные сканы/смешанный PDF и публичный игровой скриншот. Это проверка конкретных примеров, не общая оценка точности. Обычные журналы приложения не сохраняют содержимое документов; подробные результаты записываются только явным диагностическим скриптом. Результаты и ограничения — в `reports/multimodal_update/REPORT_RU.md`.

Официальные источники: [модель](https://ollama.com/library/qwen3-vl:4b-instruct), [локальный API](https://docs.ollama.com/api/chat), [локальность, keep-alive и настройки](https://docs.ollama.com/faq).

## Оформление интерфейса

Нейтральный графит, приглушённый изумруд и оригинальная серебристая SVG-волна. Ресурсы хранятся в `document_app/assets/`, оформление — `document_app/theme.css`, подключение — `document_app/appearance.py`. Шрифты системные: Arial с кириллицей/латиницей и monospace для небольших подписей. Внешних шрифтов, изображений и 3D-библиотек нет.

Медленное движение декоративного слоя приостанавливается в скрытой вкладке; на мобильном экране и при `prefers-reduced-motion` оно отключено. Слой не принимает клики и не вызывает перезапуски Streamlit. Изменения относятся к оформлению, маршрутизация моделей и обработка документов сохранены. Проверки и ограничения визуальной проверки — в `reports/design_refresh.md`.


### Local acceptance inputs

Private PDFs, screenshots, extracted texts, detailed diagnostic traces and local model weights are intentionally not published. Historical paths under `reports/email_diagnostic/` and `reports/multimodal_update/` refer to optional local reports, not bundled examples. The public summary is `reports/FEATURE_UPDATE.md`.

To run the opt-in real-model acceptance harness, supply local fixtures matching its documented regression cases: a lecture PDF with the email submission slide on page 30, its PNG, a timetable PDF, and a game screenshot. The generated formula and mixed/scan PDFs are written locally. These are regression-specific checks, not a general accuracy benchmark.

```bash
export DOCUMENT_QA_LECTURE_PDF=/path/to/lecture.pdf
export DOCUMENT_QA_SLIDE_PNG=/path/to/slide.png
export DOCUMENT_QA_SCHEDULE_PDF=/path/to/timetable.pdf
export DOCUMENT_QA_GAME_IMAGE=/path/to/game.jpg
.venv/bin/python scripts/check_multimodal.py
```

The normal `pytest` suite uses synthetic fixtures; the private timetable regression is opt-in through `DOCUMENT_QA_SCHEDULE_PDF`. `scripts/verify_multimodal_results.py` requires local acceptance and UI traces, which are not bundled.
